# Accessibility — Section 7 status and how to re-verify

Last full audit: **2026-08-06** (7-agent source audit + axe scan + computed
contrast). Spec: `docs/CHATBACKTEST-BUILD.md` §SECTION 7.

## How to check it

```bash
# 1. Structural — axe-core over every route's server-rendered HTML.
cd web && npm run a11y                       # local (needs the dev server)
cd web && npm run a11y -- https://chatbacktest.com

# 2. Contrast — computed from tokens.css, both themes, every surface.
cd web && npx vitest run src/lib/contrast.test.ts

# 3. Design system — one stat component, no ad-hoc hex.
cd web && npx vitest run src/lib/designSystem.test.ts
```

`npm run a11y` exits non-zero on any **critical or serious** axe violation, so
it can gate a deploy the same way `npm run seo` does.

### What the automated checks do NOT cover

Be precise about this, because a green run is easy to over-read:

- **Colour contrast is disabled in the axe run** — jsdom has no layout engine
  and does not apply Tailwind's stylesheet, so axe cannot compute it. This is
  not a gap: `contrast.test.ts` computes every text-token × surface pair
  directly from `tokens.css` in both themes, which is stronger than sampling
  whatever happens to be painted.
- **Target size is disabled** for the same reason. The `.tap-target` utility
  in `globals.css` owns it, applied to every control recipe that measured
  under 44px.
- **Only the first server render is scanned.** Menus, modals, the command
  palette, and everything the lab draws after hydration are not in that HTML.
- **A screen-reader pass has not been done.** Structure being valid is not the
  same as the experience being good.

## The WCAG 2.1 AA checklist

| Item | State | Where it's enforced |
|---|---|---|
| Text contrast ≥4.5:1 | **Pass** | `contrast.test.ts`, recomputed from tokens |
| Keyboard-reachable + visible focus | **Pass** | `focus-ring` on every native control; skip link in `layout.tsx`; focus traps in `Modal`, `DayPanel`, `CommandPalette` |
| Touch targets ≥44×44 on mobile | **Pass** | `.tap-target` under `@media (pointer: coarse)` |
| Charts have text/table alternatives | **Pass** | `EquityCurveFigure` (table), `EquityChart` (summary figcaption), `Sparkline` + `StrategyPreview` (`role="img"` + label) |
| Colour never the only signal | **Pass** | Was already true — `EvidenceMarks` glyphs, sr-only text, `fmtSignedPct` always emits a sign |
| Alt text on images and cards | **Pass** | All three OG generators export `alt`; `TradeTable` and the compare tables have captions |
| Labelled form inputs | **Pass** | Audited across auth, lab toolbar, chat, docs jumper |

## The keyboard-only pass

The spec's other acceptance criterion is "a keyboard-only pass completes the
full run-a-backtest flow". **This has not been driven by a human and cannot be
automated from here** — it needs a real browser and a real person. It is the
one outstanding item in Section 7.

What is structurally in place for it, verified in source:

1. `Tab` from page load reaches **Skip to main content** first (it is the first
   element in the body).
2. The lab's template rail, date inputs, timeframe select and **Run backtest**
   are all native controls carrying `focus-ring`.
3. Results / Trades / Chart / Rules is a proper ARIA tablist with roving
   tabindex — one tab stop, arrow keys move between views, and each tab's
   `aria-controls` now resolves to a real panel (it previously pointed at ids
   that were never rendered).
4. In the Trades table, the inspect action is a **button inside the first
   cell**, not a `role="button"` on the `<tr>` — the row-level role made every
   cell presentational, so a screen reader got the label and none of the data.
5. **Deploy** opens a native `window.confirm` stating that the freeze is
   permanent, which is keyboard-operable by construction.

When someone does run it, record the date and what broke here.

## Deliberate exceptions

- `role="img"` canvases (`CandleChart`) name the chart but cannot expose the
  series. The Trades tab is the accessible path to that data.
- The OG-image generators hardcode hex because Satori has no CSS cascade.
  `designSystem.test.ts` allowlists exactly those files and asserts the card
  mirror stays in sync with the tokens — it had already drifted once.
- `ui/StatCard` is retained but unused; `ui/Stat` is the component to use.
